# Релиз 1.7.3 — восстановлены связанные vessel-системы

Дата: 12 августа 2026 года.

## Почему выпущен этот релиз

После релиза 1.7.2 `Vessel architecture gate` показал три красных интеграционных сценария. Проверка предыдущего коммита подтвердила, что все три ошибки существовали ещё до 1.7.2. Это старые регрессии текущей стабилизации, а не последствия исправления двигателя среднего корабля.

## Исправлено

### Магазин и пустые слоты флота

Старый базовый слой магазина предполагал, что каждый элемент `world.boats` обязательно содержит лодку, и обращался к `boat.owner` без проверки. В реальном fleet-массиве между лодками могут быть `null`-слоты, поэтому открытие магазина при таком составе могло завершиться исключением.

Текущий shop-фасад теперь безопасно представляет пустые слоты только на время вызова старого слоя и после вызова восстанавливает исходный массив без изменения индексов лодок. Выбор лодки и существующая экономика не переписывались.

### Помпа и две версии input bridge

`vessel-deck-input-bridge-system` хранит захваченный ввод в `WeakMap`. Часть системы использовала модуль с `?v=3`, а zonal-water продолжал читать тот же файл через `?v=2`. Для JavaScript это два разных экземпляра модуля и раньше они имели два разных `WeakMap`.

Теперь хранилище захваченного ввода закреплено за общим `Symbol.for` на `globalThis`, поэтому версии одного bridge-модуля больше не теряют нажатия между собой. Актуальный manifest загружает bridge под новой версией. Повреждённая помпа снова видит команду запуска и выдаёт существующее событие `vessel-pump-disabled`.

### Пост водителя испытательного катера

Регрессионный тест получал `nativeVesselForBoat` из `vessel-runtime.js` без query string, тогда как игровой `free-roam-core-v8.js` использует `vessel-runtime.js?v=2`. Поскольку runtime содержит модульные `WeakMap`, тест фактически наблюдал вторую независимую копию vessel-instance.

Тест теперь использует тот же URL runtime, что и игровой core. Проверка снова относится к настоящему claim `stress-helm-control`, а не к другой копии состояния.

### Cache-buster после старого immutable-кэша

HTML-инъекция релиза принудительно переводит старые URL магазина и deck-input bridge на свежие версии. Также исправлен прямой script cache-buster клиента среднего корабля: исходный HTML всё ещё ссылался на старый `free-roam-dual-turret-client.js?v=7`, поэтому теперь он принудительно получает новый URL.

## Что не менялось

- Новых механик нет.
- Сетевая оптимизация не расширялась.
- Баланс лодок, оружия, магазина и ремонта не менялся.
- Существующие vessel-системы не заменялись новыми параллельными реализациями.

## Проверка

До публикации выполнена синтаксическая проверка изменённых JavaScript-файлов. После публикации релиз обязан пройти GitHub Actions, включая `Vessel architecture gate` с тремя сценариями, которые были красными в 1.7.2.

Реальная проверка Safari и игрового звука остаётся отдельной обязательной проверкой после зелёного CI.
